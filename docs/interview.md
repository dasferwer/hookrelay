# Как объяснить HookRelay на интервью

**Проблема:** HTTP-ошибка не всегда означает отсутствие действия у получателя.

**Путь события:** API записывает event и delivery в PostgreSQL → dispatcher
захватывает lease → RabbitMQ → worker → подписанный HTTP → запись результата.

**Главное решение:** очередь не единственное место хранения работы. Задание
можно восстановить по БД после разрыва между commit и публикацией сообщения.
Поколение lease защищает от запоздалого результата старого процесса.

**Что показать:** smoke с двумя 503, replay после 400, timeout после commit
получателя и recovery smoke с SIGKILL worker. В последнем случае доставка
повторяется, а уникальный ключ приёмника сохраняет одно бизнес-действие.

**Компромиссы:** ограниченный retry budget, нет строгого порядка, один узел
брокера. Одно бизнес-действие достигается в транзакции получателя, а не
обещанием «exactly-once HTTP» со стороны отправителя.

Корректное описание: «Реализовал портфолио-платформу вебхуков с outbox,
lease, HMAC, ограниченными повторами и проверяемым восстановлением».
